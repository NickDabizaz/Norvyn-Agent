# Norvyn code standard

This document is the mechanical and structural contract for contributions. Domain vocabulary belongs in
[`CONTEXT.md`](../CONTEXT.md); architectural rationale belongs in [`docs/adr/`](adr/).

## TypeScript and React

- Use strict TypeScript and explicit domain types at module boundaries. Browser commands and server events are
  discriminated unions; protocol handlers must be exhaustive. Network and browser payloads may not introduce
  `any`, unchecked casts, or feature logic before runtime decoding.
- Use `camelCase` for values and functions, `PascalCase` for components and types, and domain terms from the
  glossary exactly as written.
- Prefer named exports for reusable modules. Keep Node-only imports out of browser modules.
- React components render behavior; persistence, protocol translation, Markdown rendering, and data-windowing
  live in focused feature modules.
- Format with Prettier. ESLint owns correctness-oriented static rules; do not hand-format around either tool.

## Project structure

- `src/cli.ts` is the packaged executable entry point.
- `src/server.ts` composes the loopback HTTP/WebSocket host and feature routers.
- `src/features/` contains server-side feature modules with small public interfaces.
- `src/client/` contains browser feature modules and presentation.
- `src/protocol.ts` is the shared browser/server protocol contract.
- `src/transport.ts` owns the Provider-neutral `Transport` and `ThreadStore` seams plus the Codex Adapter.
- `schemas/` is generated by Codex and must never be edited by hand.
- `test/` contains outside-in behavior tests; `test/fixtures/` contains Provider process fakes.

## System design

- Keep Provider, Transport, Local Session, Thread/Chat, Turn, Workspace, Access Mode, and Boundary meanings
  aligned with the glossary.
- Provider-specific protocol details stay inside an Adapter. The rest of the product consumes advertised
  capabilities and handles unsupported operations explicitly.
- Codex owns conversation history as decided in [ADR-0001](adr/0001-codex-owns-conversation-history.md). Never
  add a parallel history database or edit rollout files.
- Updater traffic remains outside the agent Boundary as decided in
  [ADR-0002](adr/0002-update-checks-sit-outside-the-agent-boundary.md).
- Add an ADR when a durable decision changes boundaries, ownership, persistence, or a public seam.

## Testing

- Write outside-in Vitest tests at public seams. Prefer one failing tracer test followed by its minimal
  implementation.
- Provider behavior must use the process fake; no test requires a Local Session, credential, API key, or
  metered model call.
- Exercise public module interfaces and observable feature seams; do not reach through them to private state.
- Run the focused test while iterating, `npm run typecheck` regularly, and `npm run verify` before committing
  or pushing.
- Tests must assert observable behavior, not private implementation details.

UI work also follows [ui-quality.md](ui-quality.md), including the readiness contract, screenshots, keyboard,
focus, contrast, zoom, scroll, and cleanup gates.

CSS remains formatted, consumes semantic design tokens, and stays scoped to its feature. Stylelint rejects raw
palette values outside custom properties, ID selectors, and selectors broad enough to create cross-feature
specificity collisions.
